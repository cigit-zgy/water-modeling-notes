LaTeX 解决了科研论文的排版问题，但没有解决论文生命周期管理问题。一篇论文从初稿、投稿、返修到最终归档，需要同时维护正文、审稿回复、作者信息、参考文献、投稿附件以及多个版本之间的关系。

引入 LLM Agent 后，这个问题更加明显。Agent 可以访问文件并执行操作，但访问能力并不等于修改授权。科研写作需要明确区分科学内容控制和工程流程自动化。

[`sci-manuscript-skill`](https://github.com/cigit-zgy/sci-manuscript-skill) 的目标是建立一个面向科研稿件的生命周期工作流。它不负责自动生成论文，而是管理稿件状态、版本演化、差异追踪、审稿回复和投稿产物。

<AcademicCallout kind="definition">
本文中的 manuscript lifecycle engineering 指对稿件初始化、版本演化、编译、审稿回复、差异标记、回滚和投稿打包建立明确状态、规则和产物契约。
</AcademicCallout>

## 核心设计原则

系统遵循几个基本约束：

| 原则 | 实现 |
| --- | --- |
| 科学内容所有权明确 | 生命周期命令不修改未经授权的正文内容 |
| 版本状态明确 | revision 使用固定父子关系 |
| 共享资源单一来源 | 作者信息、BibTeX、revision style 位于 references |
| 正式产物和临时文件分离 | output 保存最终结果，tmp 保存运行过程 |
| 操作可恢复 | rollback 和 reindex 具有保护机制 |

因此，系统重点解决两个问题：当前稿件处于什么状态，以及什么操作被允许发生。

## 系统架构

`sci-manuscript-skill` 分为两个层次：Skill 负责 Agent 行为约束，Python package 负责具体执行。

| 层次 | 内容 | 职责 |
| --- | --- | --- |
| Agent contract | SKILL.md、references | 路由任务、限制权限 |
| Execution layer | CLI、API | 提供稳定入口 |
| Domain logic | workspace、metadata、compile、diff | 执行生命周期逻辑 |
| Runtime resources | journal templates 等 | 随 Skill 安装 |
| User workspace | manuscript | 保存用户论文内容 |

这种设计避免每篇论文复制运行代码。论文目录只保存研究者需要管理的内容。

## 用户项目结构

```text
project/
└── manuscript/
    ├── references/
    │   ├── authors.yaml
    │   ├── references.bib
    │   └── revision_style.tex
    ├── initial_submission/
    │   ├── meta.yaml
    │   ├── manuscript.tex
    │   ├── sections/
    │   ├── figures/
    │   ├── output/
    │   └── submission/
    ├── revision_01/
    │   ├── meta.yaml
    │   ├── response/
    │   ├── output/
    │   └── submission/
    └── tmp/
```

publisher 模板、编译资源和程序逻辑由 Skill 管理，不复制到用户项目。

## 稿件生命周期

```text
initial_submission (r00)
          ↓
revision_01 (r01)
          ↓
revision_02 (r02)
```

每次 revision 都基于上一版本创建，保证 marked manuscript、response location 和 provenance 具有唯一来源。

## 审稿修改追踪

返修过程中需要记录修改来源。系统区分：

```latex
\review{1-1}{Modified text responding to reviewer comment.}

\user{Additional author modification.}
```

删除内容通过版本差异自动检测。这样 reviewer-driven change、author-driven change 和 deletion 可以保持不同语义。

## Agent 使用原则

Agent 可以执行编译、检查、版本管理和结构化操作，但不能默认修改科学内容。研究者负责科学判断，Skill 负责保证流程一致性。

这种设计使论文项目具备可追踪、可恢复和可审计的生命周期管理能力。
